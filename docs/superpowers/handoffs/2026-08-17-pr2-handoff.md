My judgement, which the user has **not yet ruled on** — see §5: keep skipping tests for genuinely visual work (rail layout, hero scrim, drag feel, which a unit test can only fake), but write real component tests where behaviour is assertable and the plan itself already names an acceptance criterion:

- Task 10 `CrewMenu` — the plan demands "trigger focusable, Esc closes, focus returns". Testable.

Note this also affects the plan's repeated claim that testable logic must live as a pure `lib/` module "with the React hook or component as a thin binding". ## 3. What changed in the tree today, outside the plan

A security fix landed on `main` and was merged into this branch. It is unrelated to the redesign but touches files the plan's contract tests will scan.

**Commit `0d35d20` — "refuse every request when a deployment has no usable secret"**, merged here as `316b80c`. It modifies `proxy.ts`, `lib/wall.ts`, `lib/wall.test.ts`:

- `wallDecision` gained a third outcome, `"refuse"`, which short-circuits before every other rule.
- `proxy.ts` returns a 503 on `"refuse"`.
- **The proxy matcher no longer excludes `api/`, `b/`, `login`, `signup`.** They are still exempt from the wall — `wallDecision` passes them by name — but the proxy now *runs* on them.

Why it matters to you: if any PR2 task adds a route or asset that must bypass the shell/wall, the matcher is no longer where exemptions live. Put them in `lib/wall.ts` with the others. Don't "restore" the matcher exclusions — they were removed deliberately, because a path the proxy never sees is a path the 503 cannot take down.

Background, in case you touch auth: `instrumentation.ts`'s boot guard cannot protect a Vercel deployment. `VERCEL=1 next build` with no secret exits 0 and prerenders `/`, `/plan`, `/login`, `/signup` as static, so the CDN answers them without ever booting a server and `register()` never runs. Verified by experiment, not inferred.

**Production state:** `BETTER_AUTH_SECRET` is now set and the wall is live (`/` → 307 `/login`). But `main` has not been redeployed since the push, so the fail-closed behaviour is **not yet live**. The user owes one redeploy, which will also carry a rotated `ACCESS_CODE`.

## 4. Environment gotchas

These have each cost real time in this repo:

- **`npm install` must use `--ignore-scripts` on this machine.** Plain install fails: npm auto-runs `node-gyp rebuild` for `better-sqlite3` and there's no MSVC toolchain. Safe — every native dep ships prebuilts.
- **Port 3000 is taken by Docker.** Use another port for any dev/preview server.
- **Stale `.next` artifacts produce phantom tsc errors.** After switching branches you may see `.next/types/validator.ts … Cannot find module '../../app/api/…'` for routes that exist only on the other branch. `rm -rf .next` and re-run; the source is fine.
- **The test count differs by branch.** 399 on `redesign/planner-shell`, 219 on `main` — `main` doesn't have the redesign's tests. Don't read the lower number as a regression.
- **In PowerShell, `curl` is an alias for `Invoke-WebRequest`** and rejects `-s -o -w`. Use `curl.exe` and `NUL` instead of `/dev/null`.

Verification loop the plan mandates after every task:

```bash
npx vitest run && npx tsc --noEmit && npm run build
```
