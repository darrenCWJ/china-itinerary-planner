## 3. What changed in the tree today, outside the plan

A security fix landed on `main` and was merged into this branch. It is unrelated to the redesign but touches files the plan's contract tests will scan.

**Commit `0d35d20` — "refuse every request when a deployment has no usable secret"**, merged here as `316b80c`. It modifies `proxy.ts`, `lib/wall.ts`, `lib/wall.test.ts`:

- `wallDecision` gained a third outcome, `"refuse"`, which short-circuits before every other rule.
- `proxy.ts` returns a 503 on `"refuse"`.
- **The proxy matcher no longer excludes `api/`, `b/`, `login`, `signup`.** They are still exempt from the wall — `wallDecision` passes them by name — but the proxy now *runs* on them.

Why it matters to you: if any PR2 task adds a route or asset that must bypass the shell/wall, the matcher is no longer where exemptions live. Put them in `lib/wall.ts` with the others. Don't "restore" the matcher exclusions — they were removed deliberately, because a path the proxy never sees is a path the 503 cannot take down.

Background, in case you touch auth: `instrumentation.ts`'s boot guard cannot protect a Vercel deployment. `VERCEL=1 next build` with no secret exits 0 and prerenders `/`, `/plan`, `/login`, `/signup` as static, so the CDN answers them without ever booting a server and `register()` never runs. Verified by experiment, not inferred.

**Production state:** `BETTER_AUTH_SECRET` is now set and the wall is live (`/` → 307 `/login`). But `main` has not been redeployed since the push, so the fail-closed behaviour is **not yet live**. The user owes one redeploy, which will also carry a rotated `ACCESS_CODE`.

## 4. Environment gotchas

These have each cost real time in this repo:

- **`npm install` must use `--ignore-scripts` on this machine.** Plain install fails: npm auto-runs `node-gyp rebuild` for `better-sqlite3` and there's no MSVC toolchain. Safe — every native dep ships prebuilts.
- **Port 3000 may be taken by Docker** — it was free throughout the 2026-08-17 session and `next dev` bound it fine. `.claude/launch.json` sets `autoPort`, so this resolves itself either way.
- **`curl` cannot reach the local dev server from the agent sandbox** (connection fails, exit 000) even while the browser loads it fine. Drive local HTTP through the browser's `javascript_tool` instead.
- **Stale `.next` artifacts produce phantom tsc errors.** After switching branches you may see `.next/types/validator.ts … Cannot find module '../../app/api/…'` for routes that exist only on the other branch. `rm -rf .next` and re-run; the source is fine.
- **The test count differs by branch.** 399 on `redesign/planner-shell`, 219 on `main` — `main` doesn't have the redesign's tests. Don't read the lower number as a regression.
- **In PowerShell, `curl` is an alias for `Invoke-WebRequest`** and rejects `-s -o -w`. Use `curl.exe` and `NUL` instead of `/dev/null`.

### 4. Drag under a live poll — the gate holds

Held a block drag open while a *second member's* edit landed, which is the case
that actually matters: an unchanging payload would prove nothing.

- Four polls carrying a newer version (v5, containing an external `addItem`)
  landed during the hold. Sampled the rendered list once a second for seven
  seconds: **one distinct state**. No stomp, source row stayed dimmed, the
  external item never appeared mid-drag.
- On release, the drop's two `moveItem` ops committed *and* the buffered payload
  flushed — the external edit appeared immediately afterwards. v5 → v7.
- **Esc mid-drag:** cancelled, order unchanged, **zero ops**, and the gate
  genuinely reopened (proved by landing a fresh external edit and watching a
  normal poll deliver it).
- **Release outside the window** (`pointerup` at -300,-300): zero ops, clean
  release. **`pointercancel`:** same.
- Finally a real `left_click_drag` with genuine pointer capture, to confirm the
  synthetic events used for the timing tests match reality: identical outcome,
  v8 → v10, server agrees.

Method note: the timing tests dispatched `PointerEvent`s and no-oped
`setPointerCapture`/`hasPointerCapture`/`releasePointerCapture`. That is a
supported path, not a bypass — `capturePointer` feature-checks all three
precisely so the component renders in jsdom (DayBuilder.tsx:68-80) — and the
real-pointer drag above cross-checks it.

### Browser-pane gotchas, on top of §5d's

- **`resize_window` with an explicit width/height corrupts the pane.** The DOM
  and media queries stay correct, but the page composites at ~30% into the
  top-left, screenshots come back scaled, and **clicks land nowhere** — including
  `ref`-based ones, which silently do nothing. `resize_window {preset:"desktop"}`
  restores it. Measure breakpoints through `matchMedia` + `getBoundingClientRect`
  and only screenshot at native size.
- **Screenshots lag the DOM by one or more tool calls**, and sometimes freeze on
  a stale frame entirely while `javascript_tool` reports the new state. Trust the
  DOM; reload to unstick the compositor.
- **The console buffer survives across sessions.** A parse error in
  `WorldMap.tsx` showed up at startup for a file that is well-formed on disk —
  a mid-edit HMR snapshot from a previous session. Check the file before
  believing the console.
- Computed colours come back as `oklab(…)` in this codebase, so regex-parsing
  `getComputedStyle().color` for RGB silently yields garbage. Resolve colours
  through a 1×1 canvas `fillStyle` instead.
